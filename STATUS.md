## Weights licence restriction

The pinned checkpoint `google/timesfm-3.0-pytorch` is distributed under the **TimesFM Non-Commercial License
v1.0**: non-commercial and non-production use only (testing, evaluation and research not tied to commercial gain,
production deployment or revenue generation), no use in end-user-facing or production systems, no redistribution
of the model or of derivatives, and a commercial licence from Google LLC for anything else. The pipeline code is
Apache-2.0 and the sample is CC BY 4.0. `NOTICE`, `MODEL_CARD.md`, the README and the notebook (header,
prerequisites and a note before the download cell) state the restriction. If it does not fit a use, the
repository's TimesFM 2.5 build (Apache-2.0 weights, commit `e47259ae75b93e7611c67e13a14d6607997c38f3`) is the
fallback.

## Before promotion

1. Run the notebook top-to-bottom on a fresh hosted runtime (`Run all`, defaults), record it in
   `docs/release-verification.md` and as a verification record in `MODEL_CARD.md`.
2. From that run, pin `MODEL_REVISION` (the commit in `resolved-revision.json`) and the `model.safetensors`
   digest in `model.py` and the manifest; remove the `revision_pending` template key; regenerate.
3. Record the BYOD positive and negative runs on the hosted runtime.
4. Confirm `date_published` for the 3.0 checkpoint from the Hub commit history.
5. Decide whether the non-commercial, non-production weights licence fits the intended use; otherwise fall
   back to the TimesFM 2.5 build.

Static/unit checks do not constitute clean-runtime notebook evidence. The repository is not release-grade
until an integrator promotes it on recorded evidence for the exact candidate commit.
